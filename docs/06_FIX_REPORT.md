# CHIHUN UX Writing OS v0.1.1 · 결함 수정 및 재검증

기준일: 2026-09-18. 비교 대상은 사용자가 제공한 v0.1.0 저장소 ZIP과 비판적 감사 보고서예요. 원본 ZIP과 Master 파일은 그대로 보존하고 별도 작업본만 수정했어요.

## 1. 수정 범위

| 감사 문제 | 수정 | 회귀 검사 |
|---|---|---|
| F01 설치 경로 이탈 | 선택 루트 아래 모든 상위 경로·링크·재분석 지점·중첩 마운트 검사, 원본 스킬 목록·해시 확인 | R01, R09~11, R14, R27~28 |
| F02 의도치 않은 배포 파일 포함 | 명시적 authored 허용 목록 + 순수 렌더러의 생성 목록만 패키징, 두 패키지의 공통 경로 검사 | R03~04, R15~16, R24 |
| F03 평가 기준 관리 원본/실행본 불일치 | 보존 원문에서 항목·문구·배점·순서·임계값을 추출해 구조화 기준과 대조, 불일치 시 빌드·검사 실패 | R05~06, R19 |
| F04 구버전 잔존 | 임시 빈 디렉터리에서 생성 후 관리 디렉터리 교체, 시작 안내·지식 파일·평가 템플릿을 VERSION에서 생성 | R07, R21, R23, R25 |
| F05 시험 원본과 실제 입력 불일치 | 단일 원본에서 작성자 입력·채점표 파생, 내용 전체와 SHA256 검사 | R08, R17~18 |
| F06 두 대상 중 부분 설치 | 모든 대상 사전 검사·복사 후 적용, 예외 시 앞서 적용한 대상까지 원복, 백업 보존 | R02, R12~13, R22 |

일반 오류의 원복 도중에도 추가 오류가 발생하면 복구 자료를 지우지 않고 남기며, 부분 복구 상태를 보고하도록 했어요(R29~30).

R01~R08은 이전 감사의 8개 재현 조건에 대응해요. R09 이후는 보호 경로, 오류 주입, 압축 재검증, 검토 입력 분리 등 추가 검사예요. 의도적으로 만든 시나리오 통과를 전체 오류 확률이나 보안 인증으로 해석하지 않아요.

## 2. 라이팅 원문의 보존

주요 GOLD·추가 원문 사례·Synthetic·점수·Hard Fail·원문 계약과 지도는 기존 데이터와 대조해요. 규칙 본문과 적용 조건도 유지했어요. 실행 버전은 core/rules.json에 중복 저장하지 않고 VERSION으로 통일했어요.

실행용 평가표는 score.json과 hard-fails.json에서 만들되, 보존된 원문 계약과 항목별로 일치해야 생성할 수 있어요. 원문 파일을 제공하는 검사는 원문 SHA256·줄 번호·발췌까지 대조해요. 단순히 새 해시를 저장했다는 이유로 의미 변경을 통과시키지 않아요. 승인된 평가 기준 변경은 별도 설계·버전 결정이 필요해요.

## 3. 개발용 시험 보완

기존 20개에 12개 가상 사례를 추가해 32개로 구성했어요. DRAFT 7, WASH 10, REVIEW 15예요. 각 사례에 필수 의미·금지 의미·범위·미확인 사실 처리 기준을 추가했어요. 직접 시험에 연결되지 않았던 6개 규칙도 연결했어요.

이는 시험 정의의 보완이지 모델 성능 결과가 아니에요. 모두 assistant가 만든 공개 개발용 문제이며 GOLD나 블라인드 세트가 아니에요. 실제 모델 응답과 사용자 수용 검토는 없어요.

## 4. 실제 실행한 검사

- `verification/static.json`: 파일·참조·원문·정확한 재생성·입력 투영 검사
- `verification/installer.json`: 기존 정상 설치·업데이트·백업·dry-run 10개 검사
- `verification/regressions.json`: 감사 재현 조건과 추가 오류 경로 30개 검사
- `verification/source-preservation.json`: 원본과 보존해야 할 데이터의 동일성
- `verification/coverage.json`: 시험 정의의 요청 유형·규칙 연결 현황
- `verification/agent-availability.json`: 현재 실행기·연결 확인 범위

로그는 실행된 것만 기록해요. 실패한 중간 구현은 수정 후 재검사했고 최종 배포에는 최종 실행 결과를 포함해요. 최종 로그의 테스트 수·실패 수로 확인하세요.

## 5. 독립성과 남은 한계

실제 독립 에이전트·외부 모델 실행은 0회예요. 연결 가능한 플러그인을 검색했지만 설치되어 즉시 호출 가능한 독립 검토 도구는 확인하지 못했고 Codex/Claude CLI도 없었어요. 별도 API 키를 찾거나 계정을 설치·연결하지 않았어요.

`review/`와 `scripts/prepare_review.py`는 실제 외부 실행을 위한 준비물이에요. 작성자 작업 폴더에는 채점표가 들어가지 않는지 검사했어요. 그러나 형제 폴더 접근을 막는 호스트 권한까지 이 스크립트가 설정하는 것은 아니에요. 각 역할은 별도 세션과 허용 루트에서 실행해야 해요. 원문 전체는 검토자가 별도로 제공해야 해요.

정적 링크와 통상적인 복사·이름 변경 실패를 시험했어요. 악의적 동시 파일시스템 변경, 강제 종료·전원 손실, macOS/Windows 실행, 실제 호스트의 스킬 탐색·호출, 자연어 품질, 공개 플러그인 심사·등록은 검증하지 않았어요.

## 6. 배포 판단

알려진 6개 기술 결함을 수정하고 해당 재현 조건에 대한 회귀 검사를 수행한 로컬 시험용 패키지예요. 개인 테스트를 위한 새 패키지를 제공하되, 독립 검토나 실제 라이팅 품질이 통과된 운영판으로 표시하지 않아요. 원본 0.1.0은 비교 자료로만 보존해요.
