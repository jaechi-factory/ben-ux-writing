# ChatGPT 사용 설정

## 권장 시작: 프로젝트용 설정

설정과 기준 파일을 직접 적용해 결과를 검토하는 경로예요. 프로젝트는 관련 대화·파일·지침을 함께 관리하고 프로젝트 지침은 해당 프로젝트 안에 적용돼요. 계정과 워크스페이스 설정에 따라 제공 방식은 달라질 수 있어요. [D3]

1. ChatGPT에 라이팅 작업용 프로젝트를 만들어요.
2. `chatgpt/PROJECT_INSTRUCTIONS.md`의 본문을 프로젝트 설정의 지침에 붙여 넣어요.
3. `chatgpt/CHIHUN_KNOWLEDGE_0.1.3.md`를 그 프로젝트의 참조 파일로 추가해요.
4. 같은 프로젝트에서 실제 문구와 확인된 제품 조건을 제공해요. `chatgpt/REQUEST_EXAMPLES.md`를 사용할 수 있어요.

ZIP 자체를 첨부하는 방식이 아니라 압축을 풀고 개별 지식 파일을 추가하는 안내예요. 설정되었다고 자동으로 모든 대화에 적용되는 것은 아니에요. 실제로 읽은 파일과 버전을 확인할 수 있게 요청하고, `evals/`의 개발용 입력으로 동작을 점검해요. 지침과 지식 파일의 버전을 맞춰요.

## 일반 대화에서 한 번 사용

프로젝트를 쓰지 않는 경우 `chatgpt/SINGLE_CHAT_STARTER.md`를 새 대화에 붙여 넣고 실제 문구를 이어서 제공할 수 있어요. 해당 대화용이며 계정 설정 변경이나 다른 대화까지의 지속 적용을 보장하지 않아요. 파일이 길게 잘린다면 프로젝트 방식으로 지식 파일을 별도 추가해요.

## 플러그인 경로

`plugin/`에는 공식 문서의 최소 구조에 맞춘 root `plugin.json`과 `skills/`를 만들었어요. MCP 서버·인증·외부 전송·실행 훅은 포함하지 않아요. [D4]

로컬/저장소 마켓플레이스 구성도 `.agents/plugins/marketplace.json`에 있어요. `source.path`는 저장소 루트 기준 `./plugin`이에요. 해당 기능을 지원하는 Codex 환경에서 저장소 루트를 로컬 마켓플레이스로 등록할 수 있어요. [D4]

```sh
codex plugin marketplace add .
```

그 뒤 공식 문서에 따라 ChatGPT 데스크톱의 로컬 소스에서 설치·새 대화 호출을 확인하는 단계가 필요해요. 로컬 경로 등록이 ChatGPT 웹 계정에 ZIP을 업로드해 즉시 활성화하는 것과 같지는 않아요. 웹·모바일 공유/공개 디렉터리 게시도 별도 절차예요. 이 패키지는 등록·심사·설치·활성화가 끝난 상태가 아니에요. 사용자 계정의 로컬/비공개 설치 가능 여부도 확인하지 않았어요.

플러그인 설치가 가능한 환경에서는 선택 목록에서 해당 스킬을 명시 호출할 수 있어요. [D1] 선택 목록에 없는 이름을 입력하는 것만으로 스킬이 설치되지는 않아요.

## 업데이트

원본 저장소의 `core/`, `templates/`에서 변경하고 `scripts/build.py`로 두 형태를 함께 생성해요. 프로젝트 지침과 지식 파일을 같은 버전으로 교체해요. 새 대화에서 확인해요. 대화 중 선호를 말한 것만으로 GitHub·설치본·프로젝트 파일이 자동 갱신되지는 않아요.
