# 07 · EVALUATOR 운영 규칙

먼저 평가하고 필요한 부분만 수정해요. 이 기준은 원문 #102~104를 보존하며, 개입·검증 상태 처리는 v0.1 운영 확장이에요.

## 평가 순서

1. 사실·필수 의미: 입력된 상태·원인·금액·시간·가능 기능·변수와 일치하는지 확인해요. 모르는 것은 ‘검증 안 됨’이에요.
2. 개입·범위: 요청한 범위에서 문제를 해결했는지, 적절한 문구를 불필요하게 수정했는지, 필요한 정보를 삭제했는지, UI 문제를 문장으로 덮었는지 확인해요.
3. 정보 구조: 중요한 정보가 결정 시점에 보이는지, 주변 UI와의 역할이 분리되어 있는지 확인해요. 버튼 하나에 모든 내용을 강제하지 않아요.
4. 문구·선호: 쉬운 한국어, 구체성, 간결함, 톤, 실제 선호와 적용 조건을 확인해요.

## 판정

- 실제로 성립하는 Hard Fail이 하나라도 남아 있으면 통과시키지 않고 재작성 또는 필요한 구조 개선·확인으로 돌려요.
- 원문 점수표의 모든 항목을 평가할 수 있을 때만 합계를 내요. 90점 미만이면 재작성해요.
- 확인하지 못한 사실이 있으면 ‘문제없음’으로 채우지 않아요. 모든 항목을 평가하지 못한 경우 총점은 null이에요. 분모 변경·만점 대입은 하지 않아요.
- KEEP 자체에는 새 문구가 필요하지 않아요. 평가용 정답과 다른 표현·개입이어도 허용 해법을 충족하면 자동 탈락시키지 않아요.
- 평가자도 오류가 있을 수 있어요. 자동/자체 평가는 사람의 수용 검토와 별개로 기록해요. 이 패키지의 구조 검사를 문구 품질 검사로 보고하지 않아요.

## 보고

핵심 오류·관련 규칙·사용자 영향·수정이 필요한 대상을 기록해요. 실측하지 않은 점수, 검토하지 않은 화면 전체의 통과, 실제 실행하지 않은 외부 모델 평가를 만들어내지 않아요.

HF-08은 원문 #23의 ‘확인/다음 절대 금지 아님’과 함께 읽어요. 중요한 행동을 설명하는 정보가 실제로 없는지 확인해요. 원문 HF의 문장은 아래 자동 생성 영역에서 그대로 보존해요. 이 맥락 연결은 운영 해석이며 단어 금지 규칙으로 대체하지 않아요.
